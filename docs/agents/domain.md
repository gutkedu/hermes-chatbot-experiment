# Domain docs

O repositório usa um único contexto de domínio.

## Antes de trabalhar

- Leia `CONTEXT.md` na raiz, quando existir.
- Leia os ADRs relevantes em `docs/adr/`, quando existirem.
- A ausência desses arquivos não bloqueia o trabalho.

## Vocabulário

Use nas Issues, testes e código os termos definidos em `CONTEXT.md`. Se um conceito necessário ainda não estiver no glossário, evite inventar sinônimos e registre a lacuna para uma futura revisão do domínio.

## Conflitos arquiteturais

Se uma proposta contrariar um ADR existente, declare o conflito explicitamente em vez de substituir silenciosamente a decisão anterior.
